How the Internet Works — URLs, DNS & Servers
What really happens when you type a web address and press Enter? A request goes out and a response comes back — in less than a second.
🌐 The journey of a web page

1. You type a URL (web address) such as https://www.example.com into your browser. 2. The browser asks the DNS — the Internet’s phone book — for the site’s IP address. 3. The browser sends a request to that server. 4. The server sends back a response: the page’s files (written in HTML). 5. The browser shows the page.

🍽️ The restaurant analogy

You are the client (customer) · the Internet is the waiter carrying messages · the server is the kitchen that prepares the order. One kitchen serves many customers, just as one server serves many clients. Servers live in huge buildings called data centres.

🔒 HTTP and HTTPS

HTTP = HyperText Transfer Protocol — the rules for requests and responses. HTTPS adds encryption: data is scrambled so only you and the server can read it — shown by the padlock.

🧩 More web words

Domain name — the readable name (example.com); .in is India’s country domain · 404 — page not found · cookies — small pieces of data a website stores in your browser · cache — saved copies so pages load faster · browser (Chrome, Safari) vs search engine (Google, Bing).

🎭 Activity — role-play

One student is the client, one the DNS, one the Internet “waiter” and one the server. Act out a request for a web page and its response.

✨ Fun facts
• The first website, made by Tim Berners-Lee at CERN, went online in 1991 — and you can still visit it at info.cern.ch.
• There are well over a billion websites, though most are not actively updated.
• The famous “404” error simply means the server could not find the page you asked for.
