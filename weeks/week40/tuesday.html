Final Project Work & Presentations
Build a small project of your choice, then present it. Ideas: turtle art, quiz game, calculator, story generator, pattern maker.
🗒️ Plan

Choose an idea that fits the time. List must-have features and nice-to-have extras. Build the smallest working version first, then add features. Beware “feature creep” — adding too much and finishing nothing.

🧮 Calculator
a = float(input("First number: "))
op = input("Operation (+ - * / **): ")
b = float(input("Second number: "))
if op == "+":
    print(a + b)
elif op == "-":
    print(a - b)
elif op == "*":
    print(a * b)
elif op == "/":
    if b == 0:
        print("Cannot divide by zero!")
    else:
        print(a / b)
elif op == "**":
    print(a ** b)
📚 Story generator
import random
animal = random.choice(["cat", "dragon", "robot"])
place = random.choice(["the Moon", "a jungle", "school"])
print(f"Once upon a time, a {animal} went to {place}.")

An f-string (with f before the quote) puts variables inside { } straight into text.

✅ Good habits

Use meaningful names (score, not x) · add comments · split code into functions · test after every small change · save a copy of the working version before big changes · ask users for feedback.

🎤 Present

Say: what it does, one thing you learned, and one bug you fixed. Showing a fixed bug proves real learning.

✨ Fun facts
• Many famous apps began as small student or hobby projects.
• Programmers call the smallest working version a “minimum viable product” (MVP).
• Giving and receiving feedback is a key skill for every software team.
